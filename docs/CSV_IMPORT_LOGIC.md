# CSV 임포트 로직

관련 이슈: [#69](https://github.com/Digginn/Diggin-app/issues/69)

2026.10.15에 확인한 최신 기능명세 IMP-001~011·FLD-008을 기준으로 `prepareCsvImport`가 파일 바이트를 검증하고 저장 계획을 계산한다. 로그인·네트워크·DB 의존성이 없으며, 기존 CSV 화면의 실제 저장 콜백은 아직 연결하지 않는다.

## 입력과 출력

- 파일 이름과 원본 `Uint8Array`를 받는다. 파일 선택기의 크기 메타데이터 대신 실제 바이트 수로 5MB를 검증한다.
- UTF-8을 strict decode하고 BOM을 허용한다. Expo 57의 기본 `TextDecoder`를 사용한다.
- `importedAt`은 실행 시작 시각을 한 번만 정해 전달한다. 유효하지 않은 CSV 등록일은 모두 이 시각을 사용한다.
- `registeredAtUtcOffsetMinutes`는 CSV 원본 시간대를 호출부가 명시한다. 기기 시간대에 따라 날짜가 달라지지 않도록 기본값을 추측하지 않는다.
- `isKrw`는 팀에서 검증한 스토어/도메인 통화 규칙을 적용하는 함수다. 생략하거나 확인되지 않으면 가격은 NULL이다.
- `existingProducts`는 로그인 사용자 범위에서 조회한 URL·ID·폴더·소장 상태만 전달한다. 가격·이미지 등 기존 저장 정보는 변경 계획에 포함하지 않는다.
- `existingFolderNames`는 계정의 전체 일반 폴더 이름 목록이다. 비어 있으면 `[]`를 명시한다. 소장템 고정 폴더는 50개 제한에서 제외하며 이름 충돌 검사에서는 예약한다.
- `previousFolderMappings`는 동일 Import의 재시도에서 확정된 원본 버킷명→최종 폴더명을 유지하는 입력이다. 호출부는 해당 Import의 `folderMappings`를 보존해 전달해야 한다.
- 상품명·브랜드명은 NFC로 정규화하고 앞뒤 공백을 제거한 후 100자·30자로 자른다. 프로젝트의 `unicode-segmenter`를 사용해 한글 조합·이모지를 중간에서 끊지 않는다.
- 가격은 정확한 십진 문자열 또는 NULL로 반환한다. CSV의 소수·음수·잘못된 가격은 저장하지 않고 행 처리를 계속한다.
- 성공 반환은 DB 저장 성공이 아닌 **저장 전 계획**이다. `newProductCount`와 실패·중복 수의 합이 전체 대상 행 수다. 빈 물리 줄은 대상에서 제외한다.
- `rowNumber`는 Header를 포함한 원본 물리 행 번호다. quoted field의 개행도 반영한다.

## 병합과 폴더 관계

동일 파일의 URL 중복은 유효 등록일(오류 시 Import 시각)이 가장 최근인 행의 상품 정보로 병합하며, 모든 일반 폴더 이름과 소장 Y 관계를 합친다. 같은 시각의 행은 먼저 나온 행을 대표로 유지한다.

기존 ALL 중복은 신규 상품을 만들지 않고 빠진 폴더·소장 관계만 계산한다. 신규 상품의 이미지는 NULL(공통 Placeholder)이며 URL 재추출을 수행하지 않는다. 일반 폴더의 이름과 소장템 kind는 별개이므로 폴더 이름만으로 소장 상태를 판단하지 않는다.

버킷명을 쉼표로 분리하고 trim한다. 원본 버킷마다 Import 전체에서 동일한 최종 이름을 사용한다. 최초 후보는 앞 7자이며, 기존 계정 폴더 또는 다른 원본 버킷에 배정된 이름과 충돌하면 2부터 가장 작은 사용 가능 번호를 붙인다. 번호까지 포함해 7자 이내가 되도록 앞부분을 줄인다. 특정 이름 3종에 대한 치환은 사용하지 않는다.

길이는 프로젝트의 grapheme 기준으로 공백을 포함해 계산하고, 절단 후 끝에 남는 공백도 trim한다. 명세 예시의 문자열 길이보다 명시된 7자 상한과 trim 조건을 기준으로 한다.

새 폴더는 CSV의 유효 행에서 원본 버킷이 처음 등장하는 순서로 계획한다. `foldersToCreate`는 실제 생성할 후보 목록이고, 기존 일반 폴더와 합해 최대 50개다. 이 순서는 명세에 별도 우선순위가 없어 채택한 결정적 구현 순서다.

50개를 넘는 폴더 관계는 `folderFailures`에 행 번호·상품명·원본 버킷명과 `FOLDER_LIMIT_EXCEEDED`로 수집한다. 상품 자체와 성공한 다른 폴더 관계·소장 Y는 유지한다. 폴더 실패는 상품 행 `failedCount`와 분리하며, 연결이 하나도 없는 상품도 ALL 저장 후보에 포함한다.

동일 Import 재시도는 `previousFolderMappings`로 이름을 다시 바꾸지 않으며 확정 완료된 상품을 재생성하지 않는다. 새 Import와 기존 폴더의 충돌은 이름 suffix 규칙을 적용한다.

## 후속 저장 연결

이 모듈은 공통 스키마가 준비된 이후 서버 저장 트랜잭션에 연결한다. 연결 시 다음 사항을 적용한다.

- 인증된 사용자 범위·URL 중복·동시 저장을 서버에서 재검증한다. 전달한 기존 데이터만으로 중복 방지를 완료했다고 간주하지 않는다.
- 일반 폴더의 고유 이름·1~7자·50개 제한, 허용 색상과 폴더 추가 시각을 서버에서 다시 검증한다. 동시 요청으로 계획 시점과 실제 상태가 달라질 수 있다.
- 폴더 생성·연결 실패 시 상품 저장 및 다른 성공 관계를 롤백하지 않는다. 준비 단계의 한도 실패와 실제 DB 연결 실패를 함께 수집한다.
- Import 매핑과 확정 완료 건을 보존하고, 네트워크 재시도는 완료 건을 제외한 미완료 건에 적용한다. 현재 모듈은 재시도 입력을 처리하며 실제 네트워크·DB 실행은 하지 않는다.
- 소장 관계를 추가하면 wish_level을 NULL로 갱신한다. 기존 이름·브랜드·가격·이미지·saved_at은 유지한다.
- 실제 저장이 완료된 뒤에만 기존 `CsvImportResult`로 변환하여 UI에 성공 수를 전달한다.
- DB 결과를 반영한 Import 기록과 표준 실패 사유를 저장한다. 현재 `failedCount`는 파일 처리 단계의 실패 수다.
